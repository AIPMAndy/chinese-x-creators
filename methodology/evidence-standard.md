# 证据等级、年度口径与 X 归因

**最高原则：千万级企业经营结果 ≠ 千万级 X 内容收入 ≠ 创作者个人年净收入。**

## 为什么不能只看“年入千万”的标题

报道里可能使用完全不同的指标：当期流水、销售额（GMV）、公司营收、产品毛收入、某项收入、税前个人收入、税后个人净所得，甚至把单月峰值乘以 12 作为 ARR。必须逐项记录，否则不同案例不可比较。

## 证据等级

| 等级 | 可接受资料 | 限制 |
|---|---|---|
| A · 独立可核验 | 权利人公开并可验证的交易/财务资料（含具体范围和期间） | 这并不自动代表会计师审计，需另加审计标记 |
| B · 本人披露 | 本人原帖、官网、访谈自述、有明确原话的本人采访 | 无法单凭自述确认真实性与成本 |
| C · 转述 | 可信第三方、媒体标题、二手访谈摘要 | 与本人原话冲突时优先使用直接披露 |
| D · 无收入证据 | 真实 X 账号、产品或内容可以研究 | 禁止宣传“年入百万/千万” |

## 千万级严格认证必要条件

1. **收入期间**：完整、明确的 12 个月，而非累计或单月年化。
2. **主体**：明确收入所属个人或企业、是否扣除成本及税费。
3. **金额**：人民币 1,000 万元及以上，币种与换算日可追溯。
4. **证据**：有足够可靠原始证据，并完整披露冲突/质疑。
5. **X 归因**：只有要宣传为“靠 X 年入千万”，才必须证明相应收入主要由 X 带来。

目前公开数据**不存在本研究已独立认证的个人年净所得千万级样本**。千万候选仅表示研究价值高。

## 口径陷阱与排除规则

- 总收入包括工资：不能写为“X 自媒体变现”。
- 多年累计营业额达到 1,000 万：不能写为“年入千万”。
- 单月收入达到 100 万：不能直接乘 12 写“全年千万”。
- SaaS MRR 或 ARR：为经常性业务估计，必须单独标注；不能说等于已收到的全年现金。
- 公司营收超过千万：不能写作老板个人净赚千万。
- 采访标题称超过千万、本人说接近千万：分别记录，后续采访核实。
- 没有准确的 X handle：只收在“身份待核”档案，不绑定猜测的账号。

## 原始记录

请看 [`data/revenue_claims.json`](../data/revenue_claims.json)。每条包括 `claim / amount / comparator / period / metric_type / reporting_entity / evidence_grade / source_url / source_date / verified_at / x_attribution / caveat`。`amount` 是原说法涉及的数字，不代表经过认证的实收金额。

## 收益归因

X 的贡献需通过 UTM、专属活动码、匿名化客户来源记录或明确可溯及的作者公开解释来支持。无法证明时永远使用 `unknown` 或 `related_unquantified`。**不拿曝光量、点赞或粉丝数乘任意系数估算他人营业收入。**

## 更正与隐私

研究仅引用公开资料，不保存未经许可的私有财务或个人敏感资料。收到更正后优先修复，保留修改记录。将链接失效与收入已经撤回分别记录，不擅自认为同一回事。
